## 实现与数据库

实现 `GET /orders/:id`、`POST /orders/:id/cancel`。详情采用同一条 JOIN 语句的读视图；取消以订单行 `FOR UPDATE`、状态条件更新及 `RowsAffected` 取得一次回补资格，所有库存变化同事务提交，按商品 ID 升序执行并检查 INT UNSIGNED 上限。

现有四表、状态 CHECK 和 `updated_at` 满足要求，没有修改或新增迁移。开发库版本仍为 4。服务配置强制使用字面量回环 IP；未实现认证和订单归属授权，禁止通过代理或隧道公开部署。

## 真实 MySQL 测试结果

| 场景 | 实际验证结果 |
| --- | --- |
| CREATED、CANCELLED 查询 | 200；不存在 404，非法 ID 400；不暴露幂等键、摘要或 SQL 错误 |
| 快照 | 修改当前商品 SKU、名称和单价后，历史订单快照不变 |
| 单商品取消 | 库存 20→18→20；重复取消库存保持 20 |
| 多商品取消 | 库存 20/30→18/27→20/30；金额和明细不变 |
| 同一多商品订单 20 并发取消 | 20 个 200，19 个重放；最终库存 100/200；1 个订单、2 条明细 |
| 10 个共享两件商品的不同订单并发取消 | 全部 200；库存恢复 100/200；连同先前订单保留 11 个订单、22 条明细 |
| 状态更新失败 Trigger | 返回 500，订单仍为 CREATED，库存保持扣减后 8/17 |
| 第二商品回补失败 Trigger | 返回 500，第一个商品的已执行回补撤销，订单仍为 CREATED，库存仍为 8/17 |
| 解除故障后重试 | 200，订单 CANCELLED，库存恢复 10/20 |
| 回补整数溢出 | 返回 409，状态和库存均未提交改变 |
| 取消等待订单行锁超时 | 请求 context 到期，状态和库存不变，解除锁后可成功取消 |
| 读取一致性 | 测试专用写事务交替修改完整头/明细组合；80 次详情读取均保持金额、名称与单价一致 |
| 查询 SQL 故障 | 仅在隔离库临时重命名明细表，返回安全 500；恢复表名后 200 |

每个测试都在随机 `order_api_it_*` 库中执行。测试结束后临时库残留为 0，开发库 Trigger 数为 0。

## 开发库真实 HTTP 验收

实际创建模拟订单 2，订单号 `ORD20261015063919ea4699faaa76`，购买商品 1 数量 1、商品 2 数量 2。总金额 31799 分，明细为 5999 + 25800 分。

- `GET /orders/2`：200，CREATED，两条明细和创建时间正确。
- 首次 `POST /orders/2/cancel`：200，CANCELLED。
- 重复取消：200，`Cancellation-Replayed: true`，返回相同订单数据。
- 库存下单前为 49/25，取消和重复取消后仍为 49/25。
- 数据库核对：订单 2 为 CANCELLED、两条明细合计 31799；原订单 1 保持 CREATED、5999 分。
- HTTP 验收服务已停止，18080 无监听。模拟订单保留，没有删除已有业务数据。
